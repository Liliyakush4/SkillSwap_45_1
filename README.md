# Проект «SkillSwap» — платформа обмена навыками «Я научу / Хочу научиться»

SkillSwap — одностраничное (SPA) приложение, в котором пользователи публикуют
навыки двух типов:

- “Учу” — навыки, которыми пользователь готов делиться;
- “Учусь” — навыки, которым пользователь хочет научиться.
  Сервис позволяет находить взаимно подходящие пары, отправлять заявки на обмен и
  вести список текущих/завершённых сессий. Все данные берутся из JSON-моков;
  постоянные состояния (избранное, заявки, настройки) — в localStorage.

## Структура проекта
- src/app — инициализация приложения, провайдеры, глобальные стили;
- src/pages — страницы (экраны);
- src/widgets — крупные UI-блоки страницы;
- src/features — пользовательские сценарии (избранное, заявки и т.д.);
- src/entities — сущности домена (Skill, User, Request);
- src/shared — переиспользуемые компоненты/хуки/утилиты;
- src/api — работа с мок-JSON (fetch/axios);
- public/db — моковые данные (skills.json, users.json).

## Порядок работы с Канбан-доской

1. Разработчик забирает одну задачу (Todo) с Канбан-доски, назначает себя ответственным и переводит задачу в In progress.
2. Разработчик работает в своей feature-ветке. После завершения задачи делает коммит, пушит изменения, переводит задачу в колонку Review и создает Pull Request.
3. По результату ревью тимлид мерджит код в ветку develop и переводит задачу в столбик Done, если все хорошо.
4. Если есть что поправить, тимлид переводит задачу в столбик Need Fixes. Разработчик создает новую ветку для фикса от develop и работает в ней. После исправлений делает коммит, пушит изменения и создает Pull Request.
5. Брать новую задачу можно только после того, как текущая задача мерджится тимлидом в ветку develop и попадает в столбик Done Канбан-доски.

## Ветки

- main — стабильная ветка, содержит только готовый к продакшену код.
- develop — основная ветка для разработки. Никакие изменения не вносятся напрямую — только через Pull Request (PR).
  Каждая новая задача выполняется в отдельной ветке, созданной от develop.
  Изменения вливаются обратно в develop через Pull Request.

Формат названия ветки:
<тип>/<короткое-описание-задачи>

## Используемые типы веток:

- feature/ — новая фича или компонент;
- fix/ — исправление бага;
- refactor/ — улучшение существующего кода без изменения функционала;
- docs/ — изменения в документации;
- chore/ — служебные обновления (зависимости, конфиги и т.д.).

## Запуск проекта

### Требования

- Node.js: 18+ (желательно LTS)
- npm (идет вместе с Node)

### Установка

```
npm install
```

### Запуск в режиме разработки

```
npm run dev
```

### Сборка проекта

```
npm run build
```

### Проверка кода

```
npm run lint
npm run format
```
