# Проект «SkillSwap» — платформа обмена навыками «Я научу / Хочу научиться»

SkillSwap — одностраничное (SPA) приложение, в котором пользователи публикуют
навыки двух типов:

- “Учу” — навыки, которыми пользователь готов делиться;
- “Учусь” — навыки, которым пользователь хочет научиться.
  Сервис позволяет находить взаимно подходящие пары, отправлять заявки на обмен и
  вести список текущих/завершённых сессий. Все данные берутся из JSON-моков;
  постоянные состояния (избранное, заявки, настройки) — в localStorage.

## Структура проекта

- src/app — инициализация приложения, инициализация стора, провайдеры, роутер, глобальные стили;
- src/pages — страницы (HomePage, ProfilePage, SkillPage, FavoritesPage);
- src/widgets — крупные UI-блоки страницы (SkillCard, FiltersSidebar, Header, Footer, UsersSections);
- src/features — пользовательские сценарии (логин/логаут, добавить в избранное/убрать, отправить/отменить заявку, создать/редактировать навык);
- src/entities — сущности домена (Skill, User, Request);
- src/shared — переиспользуемые компоненты/хуки/утилиты;
- src/api — работа с мок-JSON (fetch/axios);
- public/db — моковые данные (skills.json, users.json).

## Порядок работы с Канбан-доской

1. Взять задачу в работу. Разработчик берет одну задачу из колонки Todo, назначает себя ответственным и переводит задачу в In progress.
2. Создать рабочую ветку. Перед началом обновляет develop (git checkout develop → git pull). Создает ветку от develop по задаче (feature/<короткое-описание-задачи>).
3. Разработка и коммиты. Выполняет работу в своей ветке. Делает коммиты по ходу работы и пушит ветку в репозиторий.
4. Pull Request. Переводит задачу в колонку Review. Создает Pull Request из своей ветки в develop.
5. Ревью и результат. Тимлид проводит ревью. Если все ок, мерджит PR в develop и переводит задачу в Done.
6. Доработки по замечаниям. Если нужны правки, задача переводится в Need Fixes. Разработчик дорабатывает в той же ветке и том же PR (дополнительные коммиты → push). Новый PR и новая ветка не нужны. После повторного ревью тимлид мерджит PR, и переводит задачу в Done.
7. Следующая задача. Новую задачу разработчик берет после того, как текущая задача смёрджена в develop и переведена в Done.

## Ветки

- main — стабильная ветка, содержит только готовый к продакшену код.
- develop — основная ветка для разработки. Никакие изменения не вносятся напрямую — только через Pull Request (PR).
  Каждая новая задача выполняется в отдельной ветке, созданной от develop.
  Изменения вливаются обратно в develop через Pull Request.

Формат названия ветки:
<тип>/<короткое-описание-задачи>

## Используемые типы веток:

- feature/ — новая фича или компонент;
- fix/ — исправление бага;
- refactor/ — улучшение существующего кода без изменения функционала;
- docs/ — изменения в документации;
- chore/ — служебные обновления (зависимости, конфиги и т.д.).

## Запуск проекта

### Требования

- Node.js: 18+ (желательно LTS)
- npm (идет вместе с Node)

### Установка

```
npm install
```

### Запуск в режиме разработки

```
npm run dev
```

### Сборка проекта

```
npm run build
```

### Проверка кода

```
npm run lint
npm run format
```
